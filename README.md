# Hannah's Personal Website

A personal portfolio website created for a class assignment and deployed using **GitHub Pages**.

The website is intentionally a lightweight static website with a clean black-and-white aesthetic, subtle ASCII/Unicode decorations, and a focus on presenting personal background, experience, education, and projects.

---

## 1. Assignment Requirement

The class assignment requires:

> Create your own personal website that contains your name on the homepage.

The goal is therefore to create a **polished, coherent, and personal website** rather than over-engineering the technical implementation.

---

# 2. Overall Concept

The website should feel like:

> **A polished personal portfolio belonging to someone who likes computing and has a playful internet aesthetic.**

The primary visual direction is:

* Minimalist
* Black and white
* Monospace / developer-inspired
* Clean
* Slightly playful
* ASCII / Unicode-inspired

The website should combine:

**professional portfolio + subtle ASCII-art aesthetic**

It should NOT feel like:

* A generic portfolio template
* A corporate resume page
* An entire terminal emulator
* An ASCII-art showcase
* A flashy animation-heavy developer portfolio

The ASCII art is **decoration**, not the main purpose of the website.

---

# 3. Visual Design

## Colour Palette

The initial palette should remain essentially black and white.

```text
Background:       #000000
Primary text:     #FFFFFF
Secondary text:   #A0A0A0
Borders:          subtle grey / white
```

Avoid introducing lots of colours.

If an accent colour is eventually used, it should be very subtle and only if it improves the design.

---

## Typography

A monospace font should be used to reinforce the computing / ASCII aesthetic.

Potential choices:

* JetBrains Mono
* IBM Plex Mono
* Space Mono
* Courier New

Readability is more important than forcing everything into a monospace style.

---

### Placement

ASCII decorations can appear:

* Around the hero
* Between major sections
* Near the footer
* As subtle background/decorative elements

### Important

**Do not use ASCII art as project icons.**

The projects should remain professional and readable.

For example, do not make a stock-chart ASCII graphic specifically to represent FinSight or an F1 car to represent the F1 project.

Cats, flowers, stars, etc. should function as **general decorative elements**.

### Responsive behaviour

ASCII art must not break the layout.

On small screens, decorations can:

* Scale down
* Wrap appropriately
* Be simplified
* Be hidden if necessary

# 5. Technology

## Preferred stack

Use a simple static website:

* HTML
* CSS
* JavaScript

React, Next.js, TypeScript, databases, or other frameworks are **not required**.

The simplest implementation should be preferred.

This website is intended for GitHub Pages, so there should be no unnecessary backend or build infrastructure.

---

# 6. GitHub Pages

The website will be deployed through **GitHub Pages**.

The final website must work on the actual GitHub Pages deployment, not only locally.

---

# 7. Project Structure

The initial project can be kept very simple:

```text
YOUR_USERNAME.github.io/
│
├── README.md
├── index.html
├── style.css
├── script.js
│
└── assets/
    └── ...
```

`script.js` can remain minimal or even unused initially if no JavaScript interactions are required.

Additional files are fine if genuinely necessary, but avoid unnecessary complexity.

---

# 8. Website Structure

The website should initially be a **single-page portfolio** with these sections:

1. Hero
2. About
3. Experience / Education
4. Projects
5. Skills
6. Contact

A navigation bar should allow users to jump between sections.

---

# 9. Hero / Homepage

The hero must prominently display:

## Name

**Hannah**

The name should be immediately visible when the homepage loads.

## Professional identity

Something similar to:

```text
DATA · AI · PRODUCT
Applied Computing in Finance @ NTU
```

## Short introduction

A concise description of interests in areas such as:

* Data
* AI
* Technology products
* Finance / FinTech
* Software/application development

The introduction should be short and specific rather than generic.

Potential buttons/links:

```text

```

and/or:

```text

```

A small cat ASCII can be incorporated into the hero as decoration.

The About section should be similar in style to a short LinkedIn About section.

It should communicate:

* Current degree / university
* Main interests
* Interest in data, AI and technology products
* Interest in practical / applied problem-solving

The section should be concise.

Avoid generic statements such as:

> "I am passionate about technology and innovation."

unless followed by specific information that makes the statement meaningful.

# 15. Navigation

Use a simple sticky/fixed navigation bar.

Possible design:

```text
HANNAH          ABOUT   EXPERIENCE   PROJECTS   SKILLS   CONTACT
```

or a more developer-oriented design:

```text
~/hannah        about   experience   projects   skills   contact
```

Navigation should smoothly scroll to each section.

On mobile, navigation must remain usable. A hamburger menu can be introduced if necessary, but do not overcomplicate it.

---

# 16. Layout

The website should have generous spacing and a clear hierarchy.

A rough structure:

```text
HERO
  ↓
ABOUT
  ↓
ASCII DECORATION
  ↓
EXPERIENCE / EDUCATION
  ↓
PROJECTS
  ↓
ASCII DECORATION
  ↓
SKILLS
  ↓
CONTACT
```

ASCII decorations should act as occasional page breaks rather than appearing everywhere.

The overall site should remain clean.

---

# 17. Responsive Design

The website must work on:

* Desktop
* Tablet
* Mobile

Check for:

* Horizontal scrolling
* Broken ASCII art
* Text becoming too small
* Project cards overflowing
* Navigation issues
* Buttons becoming inaccessible
* Excessive whitespace

Decorative ASCII should never be allowed to break the layout.

---

# 18. Interactivity

Interactivity should remain minimal.

Potential features:

* Smooth scrolling
* Subtle hover states
* Small terminal-style typing effect
* Subtle fade-in-on-scroll effects

Only add interactions that improve the experience.

Avoid:

* Excessive parallax
* Particle effects
* Cursor effects
* Complex animation libraries
* Loading screens
* Excessive motion

The website should remain fast and simple.

---

# 19. Content Accuracy

This is a strict requirement.

**Never invent personal information.**

Do not fabricate:

* Experience
* Job responsibilities
* Awards
* Metrics
* Skills
* Project outcomes
* Employment dates
* Education details
* Links
* Testimonials

If something is unknown, use a placeholder:

```text
[ADD GITHUB LINK]
```

rather than making up information.

---

# 20. Privacy

Only include information that is appropriate for a public personal website.

Potentially include:

* Name
* Professional email
* LinkedIn
* GitHub

Do not include:

* Home address
* Student ID
* Private documents
* Passwords
* API keys
* Credentials
* Secrets
* Other sensitive personal information

---

# 21. Code Quality

Keep the implementation:

* Simple
* Readable
* Semantic
* Easy to modify
* Easy to deploy

Prefer semantic HTML such as:

```html
<header>
<nav>
<main>
<section>
<article>
<footer>
```

Use meaningful class names.

Avoid unnecessary dependencies.

---

# 22. Accessibility

The website should:

* Use semantic HTML
* Have a logical heading hierarchy
* Maintain readable contrast
* Have visible focus/hover states
* Use descriptive link text
* Remain usable without animations

Purely decorative ASCII art should be treated as decorative where appropriate.

---

# 23. Scope Control

This is a **small 10-point class assignment**.

Do not turn it into a software engineering project.

Do NOT automatically introduce:

* React
* Next.js
* TypeScript
* Backend
* Database
* Authentication
* CMS
* Contact form backend
* External APIs
* Analytics
* Blog system
* Search
* Complex filtering
* Design systems
* Component libraries

If a feature does not materially improve the website or assignment, leave it out.

**When in doubt, choose the simpler implementation.**
